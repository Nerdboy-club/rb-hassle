# Greed Island (Roblox + Rojo) — полный контекст проекта

Этот файл читает Claude Code при запуске в этой папке. Он написан, чтобы новая сессия (в том числе на другом компьютере, например на Mac) сразу поняла игру, не перечитывая историю.

## Что это

Игра по мотивам «Острова Жадности» из Hunter × Hunter. Игрок входит в игру через консоль JoyStation, собирает 100 карт в книгу (переплёт), покупает заклинания, ловит монстров, выполняет задания, проходит финальную викторину и выходит через башню Елены. Весь остров (ландшафт, города, NPC, монстры, интерфейс) строится кодом — ассеты из Toolbox не используются. Весь текст в игре — на русском. Задумана как онлайн-кооператив: много игроков на одном сервере.

- Репозиторий: `github.com/asilJPG/rb-hassle`. Игра — в ветке **`greed-island`** (запушена, ~130 коммитов поверх `main`). В `main` осталась прежняя игра про вождение (коммит `b0779a7`, трафик-ИИ, A-Chassis): ей эта работа не мешает. Сливать с `main` только по просьбе пользователя.
- Источник правил — скриншоты вики в `docs/reference/` (13 файлов: описание, кольцо, переплёт, части карты и ранги, валюта, локации, создатели, NPC, бестиарий, монстры).
- Состояние: код собирается (`rojo build`), анализатор Luau чист, тесты на заглушках проходят. Пользователь регулярно запускает игру в Roblox Studio и присылает скриншоты/логи: основная часть работает («все пиздато работает»). **В Studio не проверены** (написаны без запуска): арены боссов, гардероб героев, эффекты магии, заклинание «Полёт» с выбором, новые модели домов/NPC/монстров от `agy`, единая высота земли после последних правок. При жалобах пользователя сначала смотреть Output и скриншот.

## Запуск и проверка

```bash
rojo serve                       # Studio: плагин Rojo -> Connect (плагин нужен только этот), Connect нажимать в режиме редактирования, не во время Play
rojo build -o game.rbxl          # проверка сборки без Studio
node tools/check/build.js        # данные и логика книги на заглушках (нужен luau; LUAU=путь/к/luau)
```

- Rojo 7.7.1 (`aftman.toml`).
- **Windows:** `aftman install` кладёт `rojo.exe` в `%USERPROFILE%\.aftman\bin` (в PATH его может не быть — вызывать по полному пути). Luau: релизы `github.com/luau-lang/luau/releases` (`luau-windows.zip`, внутри `luau.exe` и `luau-analyze.exe`).
- **Mac:** `brew install aftman` (или бинарник Rojo с `github.com/rojo-rbx/rojo/releases`), затем `aftman install` в папке проекта; плагин Studio: `rojo plugin install`. Luau: `brew install luau` (даёт `luau` и `luau-analyze`) либо релиз `luau-macos.zip`. Для проверок: `export LUAU=$(which luau)`. Shell на Mac — zsh/bash, команды из этого файла работают как есть (в Windows-сессиях использовалась Git Bash).
- Анализатор: `luau-analyze --formatter=plain <файл>`. Типы Roblox ему неизвестны, поэтому строки `Unknown type`, `UnknownGlobal`, `UnknownType`, `Unknown global` игнорируются; смотреть на остальное (синтаксис, неиспользуемые переменные, ошибки логики). Удобно прогонять по всем файлам: `for f in $(find src -name '*.luau'); do luau-analyze --formatter=plain "$f"; done | grep -v -E 'Unknown type|UnknownGlobal|UnknownType|Unknown global'`.
- `tools/check/build.js` встраивает модули из `src/` в один Luau-файл (в интерпретаторе нет `io` и Roblox API) и прогоняет:
  - `data_check`: ровно 100 карт, 32 заклинания, ссылки на зоны, монстров и лавки целы, распределение рангов;
  - `logic_check`: рука, слоты, лимиты рангов, «Получить», 45 свободных слотов, round-trip профиля, выход игрока во время загрузки, сбой DataStore (старое сохранение не затирается).
  Если в `Binder`/`PlayerData`/`Hand` появляется новый `require` общего модуля — добавить его в `logicModules` в `tools/check/build.js`.
- Для сохранения прогресса в Studio включите *Game Settings → Security → Enable Studio Access to API Services*; без этого игра работает, но книга не сохраняется (в Output предупреждение «Studio access to APIs is not allowed» — не баг).
- **Dev-флаги в `Config.luau` (работают только в Studio, `RunService:IsStudio()`):** `DevGiveAllSpells` — при входе в игру выдаются все заклинания; `DevInfiniteYen` — йены автоматически пополняются до 99 999 999. Перед публикацией выключить.

## Управление в игре (ПК)

E — подобрать предмет, поговорить, войти через JoyStation / портал арены · **Tab** — книга · **G** — режим «Получить» · **T** — Тен · **Y** — Зетсу · ЛКМ — удар «Нен» (можно зажать; прицел автоматически подтягивается к ближайшему монстру) · `/` — строка «слов кольца» («книга», «получить», «тен», «зетсу»; «приращение» — запасной синоним) · Esc — закрыть окно. На телефоне — экранные кнопки (`TouchControls`).

## Механики и принятые решения

- **Книга:** 100 указанных слотов + 45 свободных (дубликаты, заклинания, еда). Карта из рук не вкладывается — место ей находит `Binder.insert`: свой слот, иначе свободный.
- **Рука:** подобранный предмет становится картой в руке (до 6). За 60 секунд её надо вложить, иначе `Hand` возвращает предмет в мир и освобождает копию. При смерти рука пропадает (заклинание «Воскрешение» её спасает).
- **Лимиты рангов:** копий одной карты на сервере не больше `Ranks.limit`; пока лимит выбран, предмет не превращается в карту. «Вернуть в исходное» освобождает копию. «Получить» копию НЕ освобождает (предмет израсходован навсегда).
- **«Получить»** (в аниме это слово кольца, раньше называлось «Приращение»): заклинание срабатывает, еда лечит, «10 000 йен» (ранг C, лимит 20) пополняет кошелёк, «Меч Истины» удваивает урон навсегда. Что делает карта, описывает `shared/CardUse.luau`, описание показывается на карте. У коллекционных карт (горшок и т. п.) эффекта нет — «Получить» их не тратит. Благословение правителя использовать нельзя.
- **Заклинание «Полёт»:** одна карта; при использовании сервер шлёт клиенту `SpellChoice`, игрок выбирает город (`SpellChoose`), и только после выбора карта тратится. Телепорт в бою на арене запрещён.
- **Йены:** хранятся числом в профиле и показываются как карта «Кошелёк» (1 карта = виртуальная, в слот не кладётся).
- **Источники карт:** предметы в мире (по рангу 1–4 узла на карту), монстры, лавки (B-карты — после 50 покупок в одной лавке), задания, казино (карты 29–32 только отсюда), конкурс (рыба Галгайда), финальная викторина (Благословение правителя).
- **Добыча с монстров:** делится по вкладу в урон (`MonsterService.distribute`): йены пропорционально доле, последний удар даёт +10% к доле (`Config.LastHitBonus`). Шанс карты = доля × (участников + 1) / 2 (соло 100%); если никому не выпало — карта у самого сильного. Приёмы-поимки (удар в слабое место, Зетсу→Тен, серия по дереву) засчитываются как полный вклад. В открытом мире вклад меньше 10% не награждается. Карта идёт в руку, при полных руках — сразу в книгу.
- **Арены боссов:** Король жук-олень, Альфа-волк и Меланиновая ящерица (поле `arena` в `Monsters.luau`) в открытом мире не появляются. Портал в Лесу/Топях открывает меню: соло, группа друзей (создаёт и запускает хозяин, до 4) или очередь на дуо/трио/квартет (45 с ожидания, потом старт с теми, кто есть, если двое и больше). У каждой группы своя площадка (6 на босса, на высоте `Config.ArenaY`=2500, вокруг невидимая стена), HP босса растёт с размером группы (`ArenaHpScale`), на бой 5 минут, выйти можно только сдавшись (кулдаун 30 с). Босс недоступен, пока копии его карты исчерпаны. Арена — отдельная ветка логики в `MonsterService` (`groundY`, `allowed`, `arena`, `onDefeated`).
- **Гардероб героев:** NPC в Антокибе продаёт образы Гона, Киллуа, Курапики, Леорио, Хисоки и Бисуке за йены (только косметика). Образ хранится в `profile.outfit`, купленные — флаги `skin_<id>`. Покупка только за игровые йены (права на персонажей Hunter × Hunter — не продавать за Robux).
- **Победа:** все 100 слотов (последняя карта — Благословение у Двана в Лимейро). Выход — Елена с «Транспортным билетом» или заклинание «Покинуть». Победителю достаётся футляр на 3 слота (три самые редкие карты, считаются при выходе).
- **Монстры:** Циклоп (удар в глаз), Пузырьковая лошадь (Зетсу, затем Тен рядом), Радиокрыса (падает в обморок), Король жук-олень (серия ударов по дереву, число растёт с группой), Меланиновая ящерица (родинка ×8), Гипердождевик (быстрый), стая Альфа-волка, три безымянных (одноглазый, слизь, червь).
- **Экономика (оценка на бумаге):** до победы нужно порядка 180 тыс. йен (покупки ~130 тыс., заклинания, билет, лекарства). Цены продажи по рангам низкие (SS 8000 … H 30, лавка платит 0.4), предметы возрождаются через 75 с, казино с матожиданием около −5%. Фарм «подобрал-продал» закрыт.
- **Безопасность сервера:** все Remote-обработчики проверяют типы, `inGame` и расстояние до NPC/лавки/портала; есть ограничения частоты (sync книги 0.5 с, лавка 0.15 с, арена 0.15 с). Клиентам нельзя доверять числа — сервер сам считает цены, лимиты и урон.
- **Запуск устойчив к ошибкам:** `Main.server` оборачивает каждый сервис в pcall (ошибка в одном не лишает игрока персонажа). `StreamingEnabled` выключен в `default.project.json`.
- **Лобби:** «реальный мир» — комната на `RealWorldPos` (0, 1500, 0). Игрок появляется там (`RespawnLocation = lobbySpawn`), заходит в игру через ProximityPrompt на JoyStation.
- **Состояние клиента:** сервер шлёт полный снимок (`State`) при каждом изменении; клиентские таймеры (рука, эффекты) тикают локально по `receivedAt`.

## Единая высота земли (важно, много возни было)

Текстуры террейна Roblox выступают над его физической поверхностью, и всё, поставленное по лучу, «тонуло». Решение:
- `WorldBuilder.terrainY(x, z)` — единственный источник высоты: луч по Terrain **+ `GROUND_LIFT` (0.9)**. Её используют дома, деревья, предметы, NPC, монстры (`MonsterService.groundAt` вызывает её). Не считать высоту своим лучом.
- Площади городов — плоские диски из деталей (`plaza()`), радиус расширяется, чтобы накрыть всех NPC города; внутри площади `terrainY` возвращает верх диска.
- Игроку при входе в игру прибавляется `HipHeight += groundLift` (`GameService.setLift`), в лобби возвращается.
- Трава на 1 stud ниже нуля (верх −1), у домов каменный цоколь уходит под землю; `Terrain.Decoration = false`; пробуется `MaterialService.Use2022Materials = false` (может не поддерживаться из скрипта — в pcall).
- Пороги «это суша» (предметы, монстры, заборы) считаются от уровня после подъёма: `> -0.8`.
- Если что-то по-прежнему тонет или парит — менять только `GROUND_LIFT` или адресно (не плодить новых способов считать высоту).

## Работа с agy (Antigravity CLI)

На машине пользователя стоит `agy.exe` (`C:\Users\asil\AppData\Local\agy\bin\agy.exe`) — другой агентский CLI (модели Gemini и др.), которым можно делегировать крупную рутинную работу (рисование моделей), чтобы не тратить токены Claude. Что оказалось рабочим:
- Каждой задаче — отдельный `git worktree` и ветка (`git worktree add ../rb-hassle-agy -b agy-models greed-island`), чтобы агент не трогал основную папку.
- Запуск: `agy --model gemini-4-argon-medium --mode accept-edits -p "Прочитай файл AGY_TASK.md в корне этой папки и выполни задачу ..."`. Задачу класть в файл `AGY_TASK.md` (длинный текст в аргументе командной строки и модель `-high` зависали). Убрать файл перед коммитом.
- Агент пишет молча (вывод только в конце), смотреть по `git status` в его worktree. Результат: анализатор Luau → `rojo build` → тесты → `git merge` ветки в `greed-island`. Тексты задач и подход: Buildings (дома), RigBuilder (NPC), Monsters (монстры).
- Можно дорисовывать им отдельные модели и эффекты; в задаче перечислять, какие файлы разрешено менять и какие имена деталей нельзя трогать (слабые места монстров: `Eye`, `Weak`, `Core`, `Mouth`; части качания NPC: `LeftArm` и т. д.).

## Известные слабые места и что проверить в Studio

1. Модели от agy (дома, NPC с лицом через SurfaceGui, монстры) не видены глазами: возможны перевёрнутые лица, щели в крышах, торчащие детали, луч удара мимо слабых мест (слизь, червь).

3. Гардероб: образы собираются из деталей, приваренных к R15/R6 — возможны смещения причёсок; восстановление оригинальной одежды при снятии.
4. Эффекты магии (`SpellFx`): нагрузка и внешний вид; круг и кольца рисуются на 2.9 stud ниже корня.

7. Баланс боя, казино, арен и прохождения считался на бумаге.
8. Бывшая жалоба «персонаж не появляется» не воспроизводилась после правок; если повторится — Output на красные строки и `[Main] <сервис>: ...`, `Players.CharacterAutoLoads`.

## Правила работы в этом репозитории

- Работать в ветке `greed-island`. Пушить в `origin greed-island` по просьбе пользователя; `main` не трогать без прямой просьбы. Не удалять `docs/reference`.
- Коммиты — короткие, по-русски, **без строки Co-Authored-By**.
- Весь пользовательский текст в игре — на русском; числа игры — только в `src/shared/Config.luau`, новая карта — одна строка в `Cards.luau`.
- Перед переименованием функций — `grep` по `src/`: модули часто вызывают друг друга лениво (`require` внутри функции, чтобы не было циклов).
- Каждая правка: анализатор Luau → `rojo build` → при изменении данных/логики `node tools/check/build.js`.
- Не писать длинный Luau через bash-heredoc с кавычками и обратными слэшами (ломается; `\\n` внутри heredoc превращается в настоящий перевод строки и портит строки Luau): использовать инструмент Edit/Write или Node-скрипт-файл; переносы строк в Luau-строках проверять глазами. Не использовать `sed` с кириллическими классами `[...]` — он режет байты UTF-8.
- Не добавлять внешних зависимостей и ассетов из Toolbox.
- Пользователь пишет по-русски, коротко и разговорно; отвечать по-русски и по делу, после правок сообщать, что проверено (анализатор/сборка/тесты) и что нужно проверить в Studio.
